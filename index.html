Connect a vault

RepoVault stores files by committing them to a repository you own. There is no server in the middle: your browser talks straight to api.github.com, and the same files can be viewed from any device.

Scope it to one repository with Contents: Read and write. That token can only ever touch this vault.

How to set this up in 90 seconds (free)
  1. Create a repo — my-vault. Make it private if you don't want anyone reading the files, or public and use the built-in encryption.
  2. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  3. Repository access: Only select repositories → pick your vault. Permissions: Contents → Read and write. Nothing else.
  4. Paste the token above and hit Connect vault. A fresh repo gets bootstrapped automatically on first upload.

Deploy this page itself with GitHub Pages (Settings → Pages → Source: GitHub Actions) so it lives at https://<you>.github.io/repovault/ and works from any device. The token stays in your browser; nothing is ever sent anywhere except GitHub.

🔒 Screen lock (passcode) — optional

Adds a passcode prompt before the app opens in this browser, plus an inactivity auto-lock. It keeps a borrowed phone or a shoulder-surfer out, and stops the saved token being used by whoever picks up the device. It is not encryption. Your files are protected by your repo's visibility and token scope, and by the vault password used when you turn on Encrypt uploads.

    Storage & history

    FAST · 2 API CALLS · NOTHING RE-UPLOADED 1 · Fold history into one commit Every file stays exactly as it is; the chain of commits is replaced by a single one. The old commits become unreachable — GitHub frees that space when it runs garbage collection, and until then the old blobs can still be fetched by SHA. Use this for routine tidying.
    SAFE · KEEP A COPY 2 · Export the vault as a ZIP Every file exactly as stored (encrypted files stay encrypted). Do this before the rebuild below, or any time you want a local backup. Verified with a real ZIP reader in the test suite.
    GUARANTEED · NEEDS AN ADMIN TOKEN 3 · Delete & rebuild the repository Reads every file into this tab first, then deletes the repository and recreates it empty with a single commit. This is the only way to reclaim space instantly and for certain: the old objects are not merely unreachable, they no longer exist. If the upload fails half-way you can restore from the ZIP above — the files are held in memory and offered to you as a download.

    Why "unreachable" is not "deleted": git keeps every object it has ever stored. A force-push removes the reference, not the object — GitHub's own guide to removing sensitive data says to contact Support to expunge them, and until then an old blob can still be fetched by anyone who knows its SHA. Deleting and recreating the repository is the only instant, guaranteed reclaim.
